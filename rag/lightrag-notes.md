# LightRAG notes

## 适用场景

LightRAG 适合大量文档之间存在复杂关系的问题，例如：

- 几百篇论文的主题演化
- 大型代码库的模块关系
- 竞品、人物、公司、事件之间的关联分析
- 长期知识库问答

如果只是几十篇文档或简单搜索，普通向量检索更省事。

## 接入前检查

- 文档是否稳定，还是每天大量变化。
- 是否需要回答“X 和 Y 有什么关系”这类关系型问题。
- 是否能接受额外的索引时间和存储成本。
- 是否有敏感文档，能否离线处理。

## 建议目录

```text
rag/
  sources/      # 原始文档，不提交敏感内容
  indexes/      # 本地索引，通常不提交
  exports/      # 可分享的摘要或图谱导出
```

## 工作流

1. 收集文档到 `rag/sources/`。
2. 清洗明显无关、重复、敏感内容。
3. 建立实体和关系索引。
4. 用 5-10 个真实问题测试检索质量。
5. 只有当关系型回答明显优于普通检索时，才纳入日常流程。

## 注意

- 不要把 LightRAG 当默认方案。
- 知识图谱也会过期，要记录索引日期。
- 对重要结论保留来源引用。
